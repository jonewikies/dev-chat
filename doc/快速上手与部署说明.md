# DevChat 快速上手与部署说明

## 1. 环境要求

- Node.js 18+
- npm

没有 Node 18 时，可参考：`server-web/install-node18.sh`

## 2. 本地启动

后端：

```bash
cd server-web
npm install
cp .env.example .env
npm run dev
```

前端：

```bash
cd app-web
npm install
cp .env.example .env
npm run dev
```

默认地址：

- 前端：`http://localhost:5173`
- 后端：`http://localhost:3000`
- 健康检查：`http://localhost:3000/api/health`

数据库会在首次启动后端时按最新 `schema.sql` 自动初始化。生产初始化不再依赖开发阶段的迁移逻辑；需要手动执行时再使用 `npm run build && npm run init-db`。

默认数据（如管理员账号）也会在空库首次启动时自动初始化；需要手动执行时使用 `npm run build && npm run init-default-data`。

## 3. 联调规则

- 前端优先读取 `VITE_API_URL`
- 未配置时，前端会按当前浏览器主机名自动推断后端为 `:3000/api`
- 后端默认允许 `localhost:5173`、`127.0.0.1:5173` 和私网 IP 的 `:5173` 来源

如果前端域名或端口不是默认值，在 `server-web/.env` 配置：

```bash
CORS_ORIGIN=http://your-host:5173,http://another-host:8080
```

## 4. 常用环境变量

前端 `app-web/.env`：

```bash
VITE_API_URL=http://localhost:3000/api
```

后端 `server-web/.env` 常用项：

- `PORT`
- `DATABASE_PATH`
- `JWT_SECRET`
- `ENCRYPTION_KEY`
- `ENCRYPTION_KEY_VERSION`
- `CORS_ORIGIN`
- `UPLOAD_DIR`
- `MAX_FILE_SIZE`
- `PROTOTYPE_MAX_ARCHIVE_SIZE`
- `PROTOTYPE_MAX_EXTRACTED_SIZE`

消息内容当前默认采用服务端 `AES-256-GCM` 加密后落库。

建议为后端单独配置稳定的 `ENCRYPTION_KEY`：

```bash
ENCRYPTION_KEY=通过 openssl rand -hex 32 生成的 64 位十六进制字符串
```

注意：

- 不要在不同环境共用测试密钥和生产密钥
- 不要频繁更换已上线环境的密钥，否则历史消息将无法解密
- 当前运行时只支持一个激活中的消息密钥，如必须轮换密钥，应该先停机做离线重加密，再切换运行时配置

## 5. 局域网访问

前端开发服务已监听 `0.0.0.0`，后端默认监听 `3000`。例如本机 IP 为 `192.168.0.44`：

- 前端：`http://192.168.0.44:5173`
- 后端：`http://192.168.0.44:3000/api`

当前实现通常不需要改源码。

## 6. 构建与部署

前端构建：

```bash
cd app-web
npm run build
```

后端构建：

```bash
cd server-web
npm run build
npm run start
```

如果数据库里已经有历史消息，且这些消息是在旧版明文逻辑下写入，可在部署前执行一次离线迁移：

```bash
cd server-web
npm run build
npm run migrate-message-encryption
npm run migrate-message-encryption -- --apply
```

说明：

- 第一次命令是预演，不会写库
- 第二次加 `--apply` 后才会真正写库，并自动先备份数据库
- 如果服务已经按新版逻辑启动过，大部分历史消息通常已经会在兼容逻辑中被自动补加密；该脚本主要用于离线核查和补漏

如果需要轮换消息加密密钥，请按“先停服务、再重加密、最后切换环境变量并启动”的顺序执行。详细步骤见 [doc/消息加密与密钥轮换方案.md](消息加密与密钥轮换方案.md)。

简单部署可直接同机启动前后端；正式环境建议用 Nginx 代理前端静态资源、`/api` 和 `/socket.io`。

## 7. 注意事项

- 原型预览走 `/prototype-preview/:previewKey/*`，不走 `/api`
- 原型建议新开标签访问预览
- 仓库详情当前按 GitLab 集成实现
- 文档、任务、缺陷支持 URL 直达

## 8. 常见问题

- 请求不到后端：先检查后端是否启动、`VITE_API_URL` 是否正确
- 跨域报错：先检查前端端口和 `CORS_ORIGIN`
- 原型打不开：先检查 zip 包是否完整、首页文件是否存在
